# Issue #137: which Git CLI lists force-added ignored files in the index?

## Conclusion

`git ls-files` is the command that lists them. Use `git ls-files -ci --exclude-standard`
(equivalently `-c -i`). It shows tracked (index) files that match an ignore rule.

`git status` does not. It never reports tracked files as ignored, so force-added ignored
files stay invisible to `git status --ignored`.

## Evidence

Primary source: the `git-ls-files` manual, Git 2.43.0 (installed locally, `/usr/share/man/man1/git-ls-files.1.gz`).

- `-c, --cached`: shows all files in the index, i.e. all tracked files.
- `-i, --ignored`: "Show only ignored files in the output. Must be used with either an explicit -c or -o. When showing files in the index (i.e. when used with -c), print only those files matching an exclude pattern." Standard ignore rules are not automatically activated, so an `--exclude*` option or `--exclude-standard` is needed.
- `--exclude-standard`: adds `.git/info/exclude`, per-directory `.gitignore`, and the user's global exclude file.

Primary source: the `git-status` manual, same install.

- `--ignored[=<mode>]` covers ignored files, but the output describes untracked and ignored working-tree items. Tracked files are not in its scope.

Verified in a scratch repo (Git 2.43.0):

- `.gitignore` contains `*.log`. `a.log` is force-added with `git add -f`; `b.txt` is tracked normally.
- `git ls-files -ci --exclude-standard` → `a.log` (the match).
- `git ls-files -ci` (no exclude option) → `fatal: ls-files --ignored needs some exclude pattern`.
- `git status --short --ignored` → only `?? .gitignore`. `a.log` is absent, so status does not surface it.
- `git status --short --ignored=matching` → also omits `a.log`.

## Notes

- The `-ci` form only checks the index. For tracked files that are ignored, the path is still in the index, so this is the form to use.
- Local git is 2.43.0. The man pages above describe that version; this behavior has been in `ls-files` for a long time, but this verification was run on 2.43.0 only.
